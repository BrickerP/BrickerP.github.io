# 05 — Implementation Truth Source

## Problem

The live Beijing loop is structurally complete but does not yet inherit the
strongest visible elements of the approved `LOOP 01` card.

## Target user

A Profile visitor entering the full-screen work from the static LOOP card.

## Goal

Translate the card's identity into the runtime without changing the product's
route, interaction, recording, accessibility, or performance contracts.

## Keep

- Update `DESIGN.md` with the approved identity tokens and single-node rule.
- Lead the visible hierarchy with `LOOP 01`.
- Add one scene-native warm-white carrier and one exact `#D9684B` closure node.
- Align scene/CSS color roles with Night, Asphalt, Warm white, Steel, and rare
  Signature vermilion while retaining muted Beijing-specific materials.
- Restyle the existing four-action toolbar as a quiet steel-rule rail.
- Move the portrait action rail to the bottom safe area.
- Retune portrait framing only where needed to restore horizon/road balance.
- Make the reduced-motion poster the canonical LOOP still.
- Update assertions that encode the old title/palette geometry.

## Cut

- Avatar work
- New controls or destinations
- Route, duration, or passage reordering
- Dashboard or LEDGER visualization inside the artwork
- Particles, global glow, repeated nodes, scan lines, or decorative grids
- New framework, runtime dependency, font download, or data service

## Defer

- A third numbered artifact
- Repository social-preview refresh outside the LOOP site
- New Profile pinned-repository strategy

## Acceptance criteria

- Desktop and `390×844` visually match the approved identity with a Visual Ralph
  verdict of at least 90.
- `LOOP 01`, the work title, and Beijing/48-second metadata are readable without
  competing with the horizon.
- Exactly one exact signature node exists in the runtime scene.
- The carrier/node survive capture performance mode and appear in WebM output.
- All four public controls, accessible names, pressed/disabled states, focus,
  keyboard shortcuts, About lifecycle, and reduced-motion opt-in remain intact.
- Phase `1` remains pixel-identical to phase `0`.
- TypeScript, static, geometry, bundle, browser, seam, performance, production
  build, and live deployment gates pass.

## Risk controls

- Prefer material/color changes over geometry expansion.
- Keep dynamic transforms phase-derived and explicitly update world matrices.
- Inspect both standard and capture-proxy material paths.
- Preserve user-owned untracked files and stage explicit paths only.
