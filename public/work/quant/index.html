Live trading execution

Private system · Strategy, universe, positions and P&L stay private

A private live-trading system on AWS that scans intraday, filters by factor, and routes bracket orders through Alpaca into a SQLite execution ledger. This sheet prints the order path, the invariants that keep it safe, and one measured regression with its method. Every number here carries its method line.

SQLite keeps the live state on one host as one file: one writer, no network hop inside the order path, and a single artifact to reconcile against the broker at startup. The regression in 03 is the cost of that choice the moment a second writer appears.

Method

Measure
Scan batch latency: wall-clock from the start of a batch to the last symbol scored, taken from the scanner's own batch timings.

One full regular session, 09:30–16:00 ET. p50 and p95 over every batch in the session.
Host
The live scanner host, unchanged between before and after.
Before
Session of 2026-10-08, backfill cron active (every 5 minutes).
After
First full session after 2026-10-09 with the cron removed.
Publish
Values land in the table with their session date. A tilde marks a read from logs rather than a controlled benchmark.

On 2026-10-08 scan-batch p95 rose from about 2.4 s to about 9.2 s with no change to the scanner itself. The cause was a backfill cron running every five minutes on the same host. SQLite admits one writer at a time; while the backfill held the write lock, the scanner's own ledger writes queued behind it, so each batch inherited the backfill's lock-hold time.

The cron was removed from the live host on 2026-10-09. The post-fix p95 is printed once a full session has been sampled under the method above; one placeholder holds its cell until then.
